# F1.1-R1: Re-detect Wheel hang investigation

Run #101 physical evidence: Controls and Advanced FFB remained responsive while the player adjusted the Force Character controls. The reported freeze followed a later Re-detect Wheel click. Do not attribute it to opening the menu or to the three channel gains without further evidence. Treat it as a hang, not a crash.

The button calls `WheelForceFeedback::refresh()` synchronously from the FFB overlay. Refresh stops test/driving effects, sends `DISFFC_STOPALL`, unacquires/releases the wheel, clears only the FFB candidate lists, enumerates attached DirectInput FFB-capable interfaces, and opens the saved candidate or a fallback. Opening sets the joystick data format, exclusive/background cooperation, disables driver auto-centering, acquires, resets the device, enables actuators, and enumerates actuator axes. The public device list and selected wheel name are rebuilt on the next UI frame. It does not rebuild SDL Controller devices or bindings, and has no WheelFFB mutex or unbounded software retry loop. DirectInput calls are synchronous and could still block the game thread.

The supplied Run #101 log shows both DD2 interfaces: one with 8 axes/108 buttons/1 POV, one with 12 axes/63 buttons/4 POVs. It selected the 8-axis interface and reported actuator readiness. A later direction-test effect failed to create (`0x80040205`). The file ends there; it has no second `WheelFFB: refreshing attached force-feedback devices` line. Thus it does not prove the Re-detect callback ran, nor does it identify a particular blocking DirectInput operation. Actuator readiness alone did not prove this endpoint could create the required constant-force effect. The failed test and hang may be related, but that relationship is unverified.

This diagnostic pass logs the UI click and return plus entry/exit of refresh teardown, enumeration, candidate inspection, and device reopening calls. The logger flushes info lines on write. On a controlled next run, the last completed phase can distinguish a stall before the click callback from a particular DirectInput call. The next action is one click with the diagnostic build and a captured log; do not repeatedly force-close or reproduce the same failing build. No Fanatec-specific profile, controller refresh, force tuning, or new effect is introduced here.

The nonfunctional Vibration slider is removed from the player menu. Native vibration continues to feed the existing Road Detail and Impact signals; an independent wheel-vibration channel remains a backlog item. Steering Load, Road Detail, Impact, Invert Wheel, and the bounded Left/Right tests are unchanged.
